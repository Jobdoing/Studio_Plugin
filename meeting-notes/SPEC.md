# 會議筆記 plugin

## 已確認目標

- 新增獨立 Studio5 plugin；不修改 GENAI 或 Studio5 平台核心。
- 使用 Azure Speech Fast transcription，台灣華語、說話者區分、原始時間軸；不使用 Groq、不部署 GPU。
- 第一段產出忠實易讀全文：保留所有發言、脈絡、例子、疑慮、否定、強調與立場，只校正辨識錯字、標點及斷句。
- 第二段以第一段全文整理會議主旨、議題、結論。分辨提議、決議與未定案，每項附來源段落。
- 移除角色視角、類比、角色版摘要與核心洞察。這一版不新增知識補充，避免超出已授權的兩段成果。

## 實作與重用

- 重用 Studio5 `studio.ai.complete`、`studio.records`、`studio.dirty`、`studio.download`、`studio.backend.fetch` 與 Component Kit。
- 外掛自有 Node 後端只負責安全轉送 Azure Speech 請求。雲端模型由 Azure 代管，金鑰只從伺服器環境取得。
- 驗證 Studio 簽署身分，限定 plugin 與案場；不接受使用者提供上游網址或金鑰。
- 原始轉錄、易讀全文、摘要分開保存於案場紀錄。原始轉錄不覆寫，全文修改後舊摘要失效。
- AI 輸入上限為 20,000 字元。全文按連續段落分批校稿並提供相鄰上下文，逐一核對來源段落識別碼；不先壓縮成摘要。
- 摘要先按段萃取議題與證據，再整合主旨、議題與結論；保留證據來源，不以任意截斷處理超限。
- 兩段各有明確操作按鈕；第一段可重試並保留已完成段落，完成後才可執行第二段。
- 程式與提示詞為英文；繁體中文畫面文案獨立放在 JSON。

## 目錄

- `plugin/meeting-notes/`：靜態外掛、資料驗證、兩段 AI 流程與畫面文案。
- `backend/`：Node 原生 HTTP、Studio 身分驗證、Azure Speech API 串接。
- `checks/`：可直接執行的 assert 檢查、mutation checks 與瀏覽器檢查。
- `README.md`：設定、啟動、操作與驗證紀錄。

## 檢查點

1. 確認平台介面、Speech 資源可用性與上傳限制；完成規格。
2. 完成 ASR 回應驗證、原文追溯及兩段處理；驗證缺段、重複段與錯誤來源。以提議、反對、未定案的合成案例檢查流程；語意忠實度另待真人錄音驗收。
3. 完成案場保存、重開、修改失效與錯誤復原；Chrome for Testing 驗證桌面與窄螢幕。
4. 執行平台 strict lint 與 mutation checks；區分模擬測試、Azure 真實呼叫及安裝後驗收。

## 驗收

- 原始轉錄缺少文字、時間或說話者時不得假裝完整；未知說話者明確保留未知狀態。
- 全文輸出對每個來源段落恰有一個結果，順序及說話者不變；整批成功前不替換現有成果。
- 摘要每個議題與結論包含有效來源；未形成決議不可自行補成決議。
- 第一段失敗保留原始轉錄及進度；第二段失敗保留全文。錯誤時不顯示完成。
- 案場切換不得將舊請求結果寫入新案場；紀錄版本衝突不得覆蓋。
- 身分驗證失敗、跨 plugin、未指定案場、上傳超限、Azure 失敗均有明確錯誤。
- 不把 key、錄音或全文寫入 log；不保留可重建的大型測試產物。
- 自動化結構檢查不能證明語意忠實度；真實中文多人錄音仍須逐段對照，特別驗證否定、條件、反對與尚未定案。

## 邊界

### 0.3.1 提交與 developer-run 後端

- 依使用者提供的 `plugin-submission-standard.md`（Studio PR #27，尚未合併）提交；只交付，不由外掛專案簽章、部署或發布。
- Studio 已指定 developer-run 路徑：`backend.url` 保持 loopback 8937，`backend.data_dir` 為 `data`；讀取平台注入的 `PORT`、`DATA_DIR`，暫存預設為 `DATA_DIR/scratch`，明確的 `MEETING_NOTES_SCRATCH` 優先。
- 可選 `FFMPEG_BIN`／`FFPROBE_BIN` 必須為絕對路徑；未設定時沿用 PATH 的 `ffmpeg`／`ffprobe`。不擅自安裝外部程式或打包金鑰。
- 以 Python 標準庫產生固定時間、權限、排序的 ZIP／tar.gz，從固定 source commit 的乾淨檔案重建比對 SHA-256。
- 未知錯誤只顯示繁體中文通用訊息，不向使用者顯示原始錯誤代碼。

### Studio 宿主錄音接入（2026-10-25，取代下方舊限制）

- 重用 SDK 3.12.0 `studio.audio.record({project_handle})`，由點擊直接觸發；宿主負責計時、停止、取消與最多 2 小時限制。
- 宣告 `uses["audio-record"]: true` 與 `uses["studio-docs"]: {"access":"read"}`；不要求 iframe 麥克風權限。
- 停止後取得釘選版本的文件參照，以 `studio.docs.fetch(ref, {}, {project_handle})` 讀取音檔，沿用試聽、轉錄、全文及摘要。下載使用 `studio.docs.download`，不重複保存錄音。
- 取消不顯示失敗；權限、忙碌、草稿預覽與讀取失敗以可理解文字呈現。切換專案後忽略舊結果，不把錄音送入新專案。
- 文件讀取上限 64 MiB；超限或讀取失敗時保留文件參照及下載入口，可重試讀取或下載後由原有上傳入口轉錄，不宣稱已取得音檔。
- 錄音停止前仍在宿主記憶體，關閉分頁會遺失；停止並保存後才視為已有備份。獨立 localhost 頁面保留現有原生錄音作為開發檢查，不作為正式 Studio 驗收證據。
- 驗證點：取消與重試、文件版本及專案一致、讀取失敗後下載可用、專案切換不污染、原生錄音既有流程。正式部署與真實麥克風證據分開記錄。

### Browser 錄音與閱讀版面（2026-10-25）

- 桌面改為較寬全文、較窄摘要的左右兩欄；窄螢幕上下排列。
- 重用瀏覽器原生 `getUserMedia`／`MediaRecorder`，不新增套件。使用者開始後才要求麥克風權限，停止後可試聽、下載音檔，再沿用既有轉錄流程。
- 關閉、取消、出錯或案場切換必須釋放麥克風。錄音未備份時明確提示並保護離開操作。
- 暫存錄音保留在瀏覽器記憶體，約 128 MiB 或接近 5 小時時自動停止並提示；不宣稱支援無限時長或分頁關閉後復原。
- 目前 Studio iframe 的 sandbox 沒有 `allow-same-origin`，原生麥克風在正式 plugin iframe 中受限。獨立本機頁面可錄音；正式整合應由平台提供宿主錄音介面，不修改或放寬平台隔離設定，也不假造未存在的 SDK API。

- 不改既有 plugin、根目錄既有修改或平台核心。
- 不建立 GPU 或新 Azure 資源；不自動安裝至正式 Studio、不發布市集。
- 連線設定及真實錄音不足時，交付可執行的實作與清楚的剩餘驗收項目，不稱正式串接完成。
