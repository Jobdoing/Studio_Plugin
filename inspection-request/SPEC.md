# 施工查驗申請單

## 範圍

- 來源為「鋼筋綁紮自主檢查.pdf」第 1 頁，實際頁名是「施工查（試）驗申請單」。
- 做成 Studio5 獨立 App plugin，側欄名稱「施工查驗申請單」。
- 新表單的「工程名稱」預填目前選取案場名稱；其他原頁範例資料、簽名與印章不預填。
- 可建立、儲存、重開並修改案場內的表單，使用 Studio5 的 project-scoped `records`。
- 列印成品參照提供的紙本第一頁，以 A4 呈現相同的主要區塊順序、表格線、欄位與簽章空位；使用者已確認目前接受大致相似的版面，不做電子簽章。
- 後續取得的「施工自主檢查表.docx」首頁是同版未蓋章的表格，作為固定文字與版面參考；不複製其中已填的工程名稱與承攬廠商。

## 欄位

- 表頭：工程名稱、表單編號、承攬廠商、工程案號、工種名稱、建造圖號、施工部位與範圍、抽（檢、試）驗名稱、檢驗性質。
- 作業：預定與實際日期／時間；作業地點；固定十列查驗明細，每列有施工作業名稱、抽（檢、試）驗項目、抽驗（樣）數量、代表數量、試樣編號、備註。
- 檢附文件與申請查驗項目：保留原頁可辨識的勾選項與「其他」文字欄。
- 查驗結果：是否符合契約規範、監造單位處理結果、補救措施、不合格數量或範圍。
- 固定說明使用同版 Word 首頁的兩段原文。

## 行為與驗證

1. 沒有選取案場時不能儲存，切換案場後只顯示該案場的紀錄。
2. 儲存後重開，所有文字、日期、明細列與勾選狀態一致；修改時使用紀錄版本，衝突不得自動覆蓋。
3. 未儲存修改時，切換頁面或案場應由 Studio5 提示；儲存失敗時保留畫面輸入。
4. 列印預覽以 A4 顯示目前表單值、勾選狀態與手簽空位；主要區塊與原頁大致相似，不顯示操作按鈕或紀錄清單。
5. 通過 Studio5 strict lint、實際瀏覽器填寫／重開／列印檢查，以及 M2 安裝後的實際畫面與版本核對。

## 實作選擇

- 重用 Studio5 現有的 `form-app` 表單模式、`studio.records`、`studio.project`、`studio.dirty` 與 `studio.print`；不加後端與外部套件。
- 表單值只存於目前案場的 plugin 紀錄，不把原掃描檔或已填的客戶資料放進 plugin。
