# 獨立立體工地外掛

## 已確認範圍

- 在 Studio5 的外掛導覽中開啟；不修改原 dashboard。
- 固定的立體工地示意模型，搭配真實缺失改善、施工日誌、查驗紀錄。
- 可動的吊車、日誌與警示物件；可停用動畫，尊重 reduced motion，外掛隱藏時停止繪圖。
- 切換案場立即清空上一案場資料；查詢使用 `scope: project` 與 SDK 的 `project_handle`，舊回應不得覆蓋新案場。
- 點選場景物件或文字按鈕開啟對應明細。手機採上下排列，保留鍵盤操作。
- 數據來源為 Studio5 既有 curated tables，不連第三方、不呼叫 AI、不需要 key、無額外後端。

## 資料口徑

| 物件 | 資料 | 指標 |
|---|---|---|
| 警示錐 | `fact_corrective_sheet` | 未撤銷的有效改善單中未完成件數、逾期件數；明細最多 20 筆 |
| 工務所日誌 | `fact_daily_log` | 2026/06/01 有效且未刪除日誌筆數、指定紀錄日；明細最多 20 筆 |
| 查驗夾 | `fact_inspection_record` | 有效且查驗未刪除的紀錄中不合格筆數；明細最多 20 筆 |

逾期依 Asia/Taipei 的查詢日期判斷。日誌不稱為「今日」，最新紀錄日期不稱為資料更新時間。查驗不合格與改善單是不同母體，不加總。零、缺值、查詢失敗分開顯示。場景建物與位置是示意，不推算工程進度或真實缺失位置。

## 簡單解法

Reuse ladder 停在第 2 階：資料與 UI 使用 Studio SDK、project-scoped data blocks 與 Kit；3D 場景重用平台內建 Three.js 0.186 與 OrbitControls，無新 dependency。既有 dashboard 的使用者釘選沒有公開 SDK，第一版右側範圍待使用者確認，不繞過介面讀取。

## 第一版交付範圍

名稱為「立體工地」。先做固定工地、必要的三類摘要操作與明細，不複製原 dashboard 的釘選功能。右側使用者釘選仍由原 dashboard 提供。

## 驗收

- 六個 SELECT 使用平台既有 curated tables，保留 project scope；客戶環境需確認資料源相容。
- 資料解析、小型 mutation 檢查、strict lint、隔離瀏覽器的案場切換／錯誤／空資料／動畫停止／點擊明細／320–1440px 版面檢查。
- 公開原始碼與安裝 ZIP，不包含正式環境資料或驗證紀錄。

## 固定日誌日期

依使用者指定，施工日誌只查目前選取案場的 2026/06/01，使用 Asia/Taipei 日期；摘要與明細使用相同日期條件。沒有該日資料時顯示當日無日誌，不改查其他日期。缺失改善與查驗口徑維持原規格。
